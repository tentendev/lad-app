The new real-device QA user returns Clerk `oauth_missing_refresh_token`, so the current automatic revoker cannot obtain a valid Apple OAuth token. This is a confirmed runtime failure, not a hypothetical gap. The QA account is retained for the fixed build; no deletion/revocation pass is recorded.

The fix obtains a fresh native Apple authorization at deletion, exchanges its single-use code on the server, verifies Apple's signed identity against the authenticated member's Apple subject and native audience, then revokes the issued refresh token before destructive data changes. Codes and tokens remain transient. The app independently checks Apple's credential state before displaying automatic revocation success. Users can explicitly choose account deletion without Apple verification, followed by manual revocation instructions. Cancellation preserves the account unless the user confirms that fallback. A new native build and actual device deletion/revocation QA remain required. Apple's [token-handling guidance](https://developer.apple.com/documentation/technotes/tn3194-handling-account-deletions-and-revoking-tokens-for-sign-in-with-apple) requires a valid refresh/access token for programmatic revocation. Do not count HTTP 200 alone as proof.
