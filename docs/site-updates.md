# 全站最近更新

進站時若有尚未讀過的公告，會自動顯示「最近更新」彈出視窗，不佔用月曆或其他功能的版面。右上角的叉叉、「知道了」按鈕和 Escape 鍵都可關閉，這台裝置的瀏覽器會記住已讀狀態。網站頂部的小鈴鐺可隨時重看最近一次公告，不保留過往更新；之後有新的公告 id，進站時就會再次彈出。這是站內通知，不需要登入或瀏覽器推播權限。

## 公告範圍

- 排期依使用者提供的更新內容公告，清楚區分官方確認與預測，尊重使用者指定的公告範圍。
- 功能只有在使用者明確要求「公告」時才發布。UI、樣式、文案與一般功能變更不自動公告。
- 公告只保留最近一次；移除歷史紀錄或修整介面本身不另發公告。

## 每次手動發布

1. 修改網站內容。若是排期，更新 `schedule.js` 和 `SCHEDULE_META.updated`，已確認的項目設為 `tentative: false`。
2. 需要公告時，將 `updates.js` 的陣列替換為最近一次公告，只留一筆。
3. 新消息使用全新的 `id`（同日第二次更新也要換 id）和台北日期。`items` 可含此次排期更新；功能項目必須經使用者明確要求公告。
4. 測試後一起 commit、push。既有 GitHub Actions 會測試並部署至 Vercel。

```js
{
  id: "2026-10-03-schedule-2",
  date: "2026-10-03",
  items: [
    { type: "schedule", title: "活動名稱｜日期已確認", body: "說明調整前後的日期。" }
  ]
}
```

新消息或日期更正使用新 id，讓已讀訪客收到提醒。單純刪減公告、調整介面或移除未獲准內容時，保留所留下公告的原 id，避免重複提醒。

## 官方同步

現有 `Sync official schedule` 工作流程由 GitHub Actions 手動觸發。成功確認並修改排期時，會將 `updates.js` 替換為該次排期公告並部署，不累積歷史紀錄。dry run 或沒有異動時不寫入公告；無法確定的排期仍沿用原本的人工確認流程。

此通知功能不會新增官方資料抓取排程。網站的排期與公告檔案設為每次重新驗證快取，訪客重新開啟或重新整理網站即可取得新版本。

```bash
node --test scripts/*.test.mjs
```
